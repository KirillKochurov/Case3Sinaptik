# Продуктовые гипотезы для VPN-сервиса

Анализ дампа БД и клиентских логов для генерации и валидации продуктовых гипотез.

## Структура репозитория

В данном репозитории находятся скрипты для анализа и итоговый отчёт:

- `generate_hypotheses.py` — скрипт для анализа CSV-дампов (написан на чистом Python, без внешних зависимостей вроде pandas).
- `analyze_all_logs.py` — скрипт для парсинга ZIP-архивов с клиентскими логами ошибок.
- `final_product_hypotheses.md` — итоговый аналитический отчёт с 4 продуктовыми гипотезами, подтверждёнными данными, и рекомендациями.
- `.gitignore` — конфигурация для исключения тяжёлых файлов данных из репозитория.

## Как воспроизвести результат

### 1. Подготовка данных

Скачайте архив с данными по ссылке из задания и распакуйте его. Убедитесь, что структура вашей рабочей папки выглядит следующим образом:

    ваша_рабочая_папка/
    ├── db/
    │   ├── users.csv
    │   ├── sessions.csv
    │   ├── orders.csv
    │   ├── user_blocks.csv
    │   ├── user_connection_logs_*.csv (7 файлов)
    │   └── logs/ (папка, содержащая подпапки с ZIP-архивами логов)
    ├── generate_hypotheses.py
    ├── analyze_all_logs.py
    ├── final_product_hypotheses.md
    └── README.md

### 2. Запуск анализа

Откройте терминал (командную строку), перейдите в папку `db` и выполните следующие команды:

    cd db
    python generate_hypotheses.py
    python analyze_all_logs.py

> **Важно:** Скрипты написаны с использованием только стандартной библиотеки Python. Установка сторонних пакетов (таких как `pandas`) не требуется.

### 3. Результат

После успешного выполнения в папке `db` появятся два текстовых файла:
- `hypotheses_report.txt` (гипотезы 1–3)
- `logs_hypothesis_report.txt` (гипотеза 4)

Их содержимое агрегировано и оформлено в итоговый документ `final_product_hypotheses.md`.

## Краткие выводы из анализа

1. **Мультиаккаунты:** Массовое злоупотребление не выявлено (0 устройств с более чем 1 аккаунтом в выборке).
2. **Лимиты трафика:** 99-й перцентиль (P99) потребления составляет всего ~44 МБ. Текущий лимит в 15 ГБ недостижим для подавляющего большинства и не работает как триггер для монетизации через рекламу.
3. **Конверсия:** 1.57% при высокой частоте повторных покупок (в среднем 2.4 заказа на покупателя). Требуется улучшение онбординга в первые 24 часа.
4. **Инциденты (ключевая находка):** 86% пользователей в выборке логов сталкиваются с критическими DNS-сбоями (признак DPI-блокировок DoH-запросов) и системными ошибками на устройствах Huawei без сервисов Google (GMS).
